# MySQL协调租约丢失取消（阶段66.4）

查询持有协调连接期间，后台监视器每250ms检查全局槽与会话锁的实际拥有者；每次数据库操作仍受协调器超时约束。连接中断、超时或锁归属不符会触发当前查询的取消，并向公共协议返回共享状态不可用，不自动补发模型请求。外部调用者取消和原有查询截止时间保留各自的异常语义。

监视器与业务协程共用租约连接，但业务期间不在该连接执行其他操作；退出时先通知监视器停止并等待有界探测完成，再释放锁。不能取消一个正在读取的aiomysql探测后直接回收连接，也不能留下脱离请求的监视任务。重复取消仍等待清理完成。

真实MySQL测试在查询正等待合成模型响应时，通过自有fixture连接执行KILL CONNECTION。原请求必须停止等待并完成模型清理，返回503，未追加会话轮次；审计保留一次已开始、用量未知的取消调用；另一个进程随后可取得配额。供应商传输边界使用合成响应，不发生外部模型调用。另有离线测试区分普通退出、业务异常、外部取消、查询超时、丢锁和重复取消。

这是有界轮询检测，不是数据库事务栅栏：网络中断到检测完成之间存在窗口，已经到达外部供应商的调用也不能据此证明未计费。审计中的缺失token保持未知。此阶段仍未提供生产多worker启动配置；连接恢复、配置和索引一致性、共享供应商限流及其他执行端点保护继续按后续清单实施。
