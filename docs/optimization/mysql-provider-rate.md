# MySQL共享供应商限流（阶段66.5）

可选共享运行时中的原生模型路由器，在每次供应商尝试前向MySQL预占一次滚动60秒配额。限额按namespace与供应商配置键共享，使用MySQL UTC时钟；事务通过配置行锁串行计数与插入。所有worker必须声明相同RPM，包括0（显式不限流）；不一致时明确不可用。非零RPM限定1–10000，每个供应商仅保留当前窗口所需的有限记录；过期记录在下次该供应商预占时清理。

配额满立即返回`QUERY_CAPACITY`，不排队等待、不自动重试或改走fallback。生成器的两种候选策略、生成节点和固定计划执行器均保留这一基础设施错误，不能把拒绝转换成SQL候选或普通生成失败。共享数据库不可用同样明确失败。未发生模型传输的拒绝不会增加模型调用与用量计数；窗口预占属于保守准入计数，与实际计费或token用量不同。

预占提交结果未知、取消或后续模型失败都不退还配额，防止未确认的外部请求被重复放行。各次重试和fallback若由其他错误触发，也各自预占对应供应商的槽。RPM为0仍检查跨worker配置一致性，但不写尝试记录。不同供应商配置键各自限流；多个别名若共用同一个外部账号，仍需在部署配置中使用统一键，不能把该机制描述为跨账号的供应商计费限额。

真实MySQL验收包括竞争一个槽、不同供应商隔离、限额不一致、窗口到期、锁等待时取消及独立服务进程之间的模型调用拒绝。离线回归确认拒绝穿过完整查询工作流时不重试，审计中的实际模型调用数为0。没有新增真实供应商调用。

默认未安装共享运行时的路由器继续使用进程内限流。生产启动与配置/连接/索引一致性仍需后续验收，本阶段不宣布生产多worker支持完成。
