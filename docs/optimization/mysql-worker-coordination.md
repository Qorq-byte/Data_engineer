# 单机多进程MySQL协调（阶段66.1，未启用多worker）

用户确认的部署目标为单机多进程、共享MySQL。此步实现`MySQLCoordinator`原语，尚未接入查询服务，不改变当前默认单worker支持范围。

初始化把namespace摘要和全局容量登记到MySQL表；同namespace不同容量的worker拒绝初始化，避免各自解释全局上限。容量变更需停服迁移登记行，不能混跑不同配置。协调账户需要创建登记表、读写登记行和使用GET_LOCK的权限；原语使用专用连接租约，连接池必须留出对应容量。

每次租约在同一MySQL连接上持有一个全局槽和一个会话锁。忙时明确拒绝，不自动重试。MySQL会话结束时释放锁；结果不确定、取消或异常时关闭连接，不回收可能残留锁的会话。正常释放也须确认锁归属。清理任务被等待，即使调用者再次取消也不脱离连接生命周期。

`tests/real_db/test_mysql_coordination.py`使用独立随机数据库与真实子进程，覆盖全局容量、同会话冲突、异常/取消、连接被KILL、进程被终止和容量配置不一致。测试不调用模型，不使用业务库。

尚未完成的66.2应用接线：全局准入错误到公共协议的映射、共享会话版本和互斥、各worker连接恢复、配置与Schema失效传播、索引写入所有权、备份/恢复协调、运行中丢锁后中止请求。尤其MySQL故障或连接丢失时，原语不能单独停止租约内已发出的远端模型调用，也不能保证撤销费用；需要服务级取消和审计未知结果。完成这些接线与整体故障验收之前，不得用此模块宣称多worker生产支持。
