# MVP优化实施计划

基准：118f9d6；分支codex/mvp-hardening；远程Qorq-byte/Data_engineer。原工作区pyproject.toml和评估文档保持原样；本分支工作树独立开发。

## 决策与范围

采用五个可独立回退的阶段，在既有节点/Runner/计划架构内渐进修复。相比全面重写，降低接口回归；相比逐点修补，第二阶段统一执行主线，避免重复流水线继续分叉。MVP明确为私有共享工作台：只有配置的管理员身份可操作业务接口，不宣称多租户隔离。外部真实模型、PG/MySQL和人工业务标注需要相应环境才可验收；离线结果不冒充线上质量。

## 阶段1：执行与访问安全

- 目标/范围：消除P0 SQL绕过、参数/超时失效、匿名业务访问、领域目录越界和秘密配置回传；修复现有MCP依赖接口，建立可运行测试基线。
- 任务：单语句AST只读策略、驱动超时与行数约束；复用JWT管理员依赖；域ID和目录边界；统一敏感设置DTO；明确生产secret检查。
- 验收：真实SQLite/DuckDB危险语句不能写入，行数及超时有效；匿名401/非管理员403；非法域不能落盘；配置出口不含密钥；既有功能测试在真实认证下通过。
- 验证：安全/节点/API测试、全量pytest、改动文件Ruff、diff与秘密文件检查。
- 交付：代码、回归测试、配置/使用文档、阶段验证记录、独立commit并push。

## 阶段2：Harness主链路与协议一致

- 目标/范围：固定YAML计划和WorkflowRunner成为JSON/SSE唯一执行路径；修复失败状态、节点依赖装配、权限和预算。
- 任务：请求级运行上下文和工具边界；统一查询服务；候选校验闸门；稳定db_id、session_id、错误/阶段/trace；取消不触发重复请求；禁止LLM选择计划。
- 验收：实际API按计划执行setup→execute→update；缺节点/未知指标/耗尽fail closed；JSON/SSE结果与会话一致；deny和调用预算真实阻断。
- 验证：Runner失败路径、合法固定SQL闭环、API协议对照、会话与SSE取消测试、全量pytest。
- 交付：统一服务、计划、接口/架构文档、阶段报告、commit并push。

## 阶段3：RAG一致性与质量起点

- 目标/范围：索引替换无残留、完整正文可检索、授权范围先过滤、过滤Schema真正进入生成prompt；版本变更不静默删库。
- 任务：文档/Schema范围替换、检索前过滤与补足K、分块参数生效；显式模型版本检查；接线SchemaRetriever/领域规则；可重跑的离线标注小集与指标输出。
- 验收：长→短/删列/删除两端集合一致；正文关键词命中且不串域；prompt含相关Schema；离线检索指标来源可追溯，不以mock向量宣称语义准确率。
- 验证：真实LanceDB/FTS5更新与检索测试、生成prompt断言、离线评测；全量pytest。
- 交付：检索修复、可重跑评测入口/数据、质量记录、commit并push。

## 阶段4：并发、恢复和可观测性

- 目标/范围：管理每库并发/连接关闭，控制模型扇出和失败恢复，提供可信分段/成功状态；消除可证明阻塞。
- 任务：有界执行和资源生命周期、Schema缓存失效、provider限流/恢复/重试总预算、readiness和结构化追踪；隔离固定SQL负载实验。
- 验收：同库并发无状态串扰、关闭无遗留；短暂provider故障能恢复；压力测试报告吞吐/分位数/错误率并限定硬件与mock范围。
- 验证：并发/取消/关闭/故障注入、分层轻量负载、全量pytest与静态检查。
- 交付：资源与观测改进、压测入口/报告、部署约束、commit并push。

## 阶段5：前端可信交互与发布文档

- 目标/范围：修复编译不确定性、演示结果混用、会话/取消/错误/空状态和基础无障碍；保持现有UI，避免整体重写。
- 任务：可复现脚本检查、显式演示状态或移除自动模拟；核心流程与管理员/服务就绪提示；对话框语义/键盘/表单关联；同步README/USER_GUIDE/实际架构说明与CI。
- 验收：干净编译检查通过，断网不产生伪执行结果；桌面/手机核心六步状态明确；gstack验证可访问名称/布局；CI不关闭既有检查，存量检查债务透明记录。
- 验证：脚本编译、gstack浏览器、API联调、全量pytest、lint/type结果与已知限制。
- 交付：交互修复、使用/部署/架构文档、最终验证、commit并push。

## 阶段完成规则

每阶段：修改→定向回归→修复→全量回归/相应检查→文档→只暂存本阶段文件→diff/敏感文件检查→提交→普通push→核对远程SHA→汇报。不会强推或合并main。新问题改变范围时，在progress.md写明证据、影响和处理决定。
