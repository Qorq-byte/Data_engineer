# 剩余优化执行计划

2026-11-05，基线为阶段60的`0fb0bca`。阶段55–60已各自上传并通过双CI，尚未合并main。用户要求逐阶段完成、验证并上传；本计划只涉及剩余优化，不代表授权发布、合并或无限预算模型调用。

## 执行顺序与完成条件

1. **61：证据收口。** 更新发布检查单中已过时的依赖安装、反馈MySQL和设置恢复缺口；区分历史告警与当前结论。交付可追溯阶段提交与对应CI，保留未覆盖边界。
2. **62：依赖兼容与安全维护。** 对当前约束组合重新审计；用当前官方资料核对阻塞项。先适配SQLGlot变化再做单项升级、差分SQL安全回归和完整双库回归；无法安全升级的包保留具体阻塞原因。安装快照与传递依赖完全锁定分别验收，不宣称直接依赖约束等于完整锁定。
3. **63：业务质量和真实评测。** 接收脱敏业务问题、Schema、人工答案，冻结dev/holdout和数据使用范围。建立导入、完整分母、失败分类和可复核报告后，准备新运行时对应的模型执行清单。获得具体预算授权后，执行真实NL2SQL及embedding对照，不复用已消费的一次性授权，不调保留集追分。
4. **64：真实端到端容量。** 在已批准供应商配额与硬停止策略内，分别测模型、embedding与完整请求；报告失败、取消、用量覆盖、延迟、吞吐与资源。合成容量只作独立对照，不能替代真实容量或账单。
5. **65：真实环境浏览器验收。** 先在自有MySQL/auth、真实只读数据库上验证连接、查询、错误、重试、取消、历史、桌面/移动/键盘；真实模型路径按对应清单执行。使用gstack browse，记录访问控制与实际readiness条件。
6. **66：多worker一致性。** 先明确同机多进程或多副本部署拓扑；设计全局准入/预算、索引单写所有权、配置与Schema失效、会话共享、备份恢复和审计一致性。实现后用真实并行进程及故障重启验收。现有吞吐探针不算多worker生产支持，完成前维持单worker支持范围。
7. **67：其余方言实库验收。** 按支持意向提供Snowflake、StarRocks、BigQuery、Redshift、ClickHouse、Databricks、Trino的独立合成实例/账号；逐个验证元数据、命名空间、原生只读、截断、超时、取消与资源释放。缺少实例的方言保持未验证，不通过模拟器宣布实库支持。
8. **68：发布验收收口。** 在干净环境重复部署、访问控制、升级、备份/恢复和回退，冻结已验证支持范围及剩余风险。发布结论按实际验收范围给出；扩大访问面和实际部署需另有明确指令。

阶段交付包括：具体提交、相关验证、最终精确SHA双CI和明确未覆盖项。依赖等待期间继续可独立完成的工作，不把不可执行项标为完成。
