# 共享查询路径（阶段66.3，候选接线）

在阶段66.1协调锁、66.2会话存储之上，新增可选的`SharedQueryRuntime`。由部署启动代码显式初始化并发布后，JSON、SSE与MCP共用的查询服务在整个工作流期间持有全局查询配额和会话锁；读取、追加轮次、版本分支与回滚使用MySQL快照及CAS令牌。新会话先占用存储配额，再调用模型。会话GET、版本列表和差异每次读取共享存储，不回退到进程缓存。

共享存储冲突映射为`SESSION_CONFLICT`/409；共享状态不可用映射为`SHARED_STATE_UNAVAILABLE`/503；全局查询或会话容量不足映射为`QUERY_CAPACITY`/503。503附带Retry-After，但服务不自动重试模型调用或不确定的写入。HTTP会话端点保留原有操作者认证；SSE与MCP使用原有协议错误封装。仅在共享快照写入确认后返回正常查询结果，失败信息不包含原始快照或数据库错误。

验收用两个独立HTTP服务进程连接一次性MySQL数据库：跨进程读取JSON/SSE/MCP查询轮次、编辑及回滚版本；确认进程会话缓存为空；模型调用阻塞时另一个进程在调用模型前被全局配额拒绝；损坏快照时查询和读取均明确失败，释放配额后其他会话仍可执行。模型只在供应商传输边界替换为合成响应，鉴权、计划、SQL执行、存储和进程协调使用真实实现，不产生供应商调用。

默认单worker路径保持原有行为。本阶段没有增加生产启动开关，运行时仅由验收fixture显式安装，因此不能把此接线描述为已支持生产多worker。后续仍需实现并验证：启动/关闭与健康状态、各worker连接恢复、配置一致性、索引写入所有权、共享限流和租约连接丢失后的主动取消，以及完整故障矩阵。共享查询锁只能约束接入该路径的操作，不能推导其他SQL端点也已获得相同保护。
