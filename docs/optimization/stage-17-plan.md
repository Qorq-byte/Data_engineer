## 顺序、范围与验收

1. 为 LanceDB/FTS5 增加按数据库备份、恢复原始记录的存储能力。备份不受搜索 top_k 限制；保留向量、时间戳、FTS 已分词文本及 metadata。校验范围并转义/参数化数据库标识，不改其他数据库。
2. 在既有替换 gate 内，embedding/来源校验完成后保存两边记录，任何删除前完成准备。同步写失败分别尝试恢复两边（其中一边失败不能阻止另一边恢复）；成功补偿仍返回索引失败，明确旧索引已恢复。
3. 补偿失败时记录进程内不可用状态，指定库检索及无范围检索拒绝返回混合数据；健康库独立检索可用。只有完整的按库替换/清空成功才解除状态。状态在 query embedding 等待后也检查，防止等待期间失败绕过。提供固定脱敏 warning，不输出底层异常秘密。
4. 真实 LanceDB/SQLite FTS5 故障注入：向量删除/插入、FTS 删除/插入（含已经写入后抛异常）、空替换、快照准备失败、补偿失败、显式重试及其他库隔离。比较完整原始记录，不只计数；保留阶段16来源/取消/并发回归。先运行新增测试证明旧实现不能满足恢复要求。
5. 定向/全量 pytest、全仓 Ruff、前端契约、34 文件 strict，通过全仓 mypy 与197项基线比对无新增诊断。记录环境/命令/结果，不把 mock embedding 功能测试称为生产性能或召回评测。
6. 更新当前协议、RAG 运维说明、阶段报告和进度；检查暂存文件/凭据，提交、普通推送、确认远程 SHA 及 Linux CI，补记远程证据。未经授权不合并主分支、不强推。

## 边界与交付

只覆盖 SchemaMetadataRAG 的 replace_db_id 路径。单文档 upsert、其他 RAG namespace、跨进程读写、崩溃/掉电恢复未承诺；恢复快照占用目标库数据量的额外内存，不能视为压测结论。同实例、同 event loop 的替换/恢复同步区间没有 await；不宣称跨系统原子性。持久数据需要运维在重启后显式全量刷新，进程内隔离标记不具备崩溃持久化能力。
