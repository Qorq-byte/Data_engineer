## 失败分类

四个失败题，两种根因，均不重跑、不调题追分：

**1. OUTPUT_BUDGET_TRUNCATION（3 题，9 个检查）**

受影响题目的每次尝试都满足 `completion_tokens == 1024`（`max_output_tokens` 上限）且 `finish_status = "length"`，候选数为 0，因此没有可导出 SQL。三题分别是 distinct/join、null/filter、having/group 组合。

这是**输出预算参数导致的失败**，不是已证明的 SQL 能力上限：预算在清单里被冻结为每题 1024 输出 token（总计 30720），本批次按该清单执行，没有临时放宽。同时也说明该模型别名对部分题目的输出长度明显高于预期，1024 不是安全的下限。若要分清“能力不足”与“预算不足”，需要另行以更大输出上限做新批次，属于新的预算与授权范围。

**2. SEMANTIC_CONSTRAINT_OMISSION（1 题，2 个检查）**

holdout 的一道 union/distinct 题：生成结果在合并的第二分支上缺少“已知用户”约束，导致 base 与 edge 场景结果集比 gold 多出记录，empty 场景因空集一致而通过。SQL 本身可执行、语法与策略校验都通过，属模型语义遗漏。该题不出现在 dev 集内，是保留集失败之一。

## 边界（不可据此外推）

- 30 题全部为**合成题集**，非业务标注，不能宣称业务准确率。
- n=1，每题只调用一次，高分位延迟与分数的抽样误差都未估计。
- `deepseek-v4-flash` 是模型别名，不保证供应商侧不可变版本；换版本后本报告失效。
- 只调用三协议共享的 `run_query` 服务一次，JSON/SSE/MCP 的公共语义由既有离线回归覆盖，不构成三份真实模型批次。
- 真实批次使用生产 keyword-only Schema 检索路径，无 embedding 请求，因此**不构成与阶段43 BM25/混合检索的对照实验**。
- 失败题的原始 SQL 与响应不回填到公开文档，也不用于调整 gold 标签。

两项已识别且未修复的问题，进入后续阶段前应作为已知事实保留：

1. 输出预算 1024 token 会稳定吃掉约 10% 的题目，需在新的预算授权内单独验证更宽预算下的真实上限。
